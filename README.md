# Бюро шифрів «Північна Зірка»

Сайт із шифром Цезаря, шифром перестановки та частотним аналізом, за
пропускним пунктом (Basic Auth / JWT / email), з даними у справжній SQLite-базі.

## Структура

```
north-star-bureau/
├── server.js                  Express: static(public/) + всі auth-шляхи
├── config.js                    порт, JWT-секрет, час дії токена, шлях до БД
├── database.js                   БД (sql.js — чистий WASM SQLite, без нативної
│                                  компіляції) — користувачі, паролі, email-коди
├── middleware/verifyToken.js     перевірка Bearer-токена
├── routes/login.js               GET /login — Basic Auth (Завдання 3)
├── routes/auth.js                 /register, /auth/login, /auth/email/*
├── scripts/generate-token.js      друк токена для перевірки на jwt.io
├── postman/*.json                 готова колекція Postman (8 запитів)
├── data/bureau.sqlite              файл бази (створюється сам при першому запуску)
└── public/                         сайт
    ├── index.html
    ├── css/styles.css                дизайн "лабораторія криптоаналітика"
    └── js/
        ├── ciphers.js                 Цезар, перестановка, частотний аналіз
        ├── i18n.js                     переклад UA/EN
        ├── nicknames.js                 позивні з відмінками
        ├── levels.js                    рівні складності (генеруються випадково)
        ├── frequency.js                  UI частотного аналізу
        ├── auth.js / gate.js              клієнт авторизації + пропускний пункт
        ├── game.js                        решта інтерфейсу
        └── app.js                          точка входу
```

## Запуск

```bash
npm install
npm start          # http://localhost:3000
```

## 1. Частотний аналіз

Нова вкладка «Частотний аналіз» у Практиці:

- вставляєте будь-який текст (зокрема шифротекст) → інструмент рахує, скільки
  разів і який відсоток припадає на кожну літеру обраної абетки (UA/EN,
  визначається автоматично, можна перемкнути вручну);
- під таблицею — **довідкова таблиця еталонної частоти літер мови** (саме
  те, про що йшлося в завданні: «табличка яка показує % на яку літеру
  абетки»), з якою порівнюють спостережений розподіл;
- алгоритм також сам підбирає найімовірніший зсув шифру Цезаря (кореляція
  спостереженого розподілу з еталонним) і кнопкою одразу відкриває
  розшифрований текст у вкладці «Цезар»;
- є пояснення, чому цей метод зламує шифр Цезаря, але безсилий проти шифру
  перестановки (той лише міняє літери місцями, не змінюючи їхню частоту).

Самі відсотки — приблизні, добре відомі в криптографії орієнтовні значення
(не точна статистика з конкретного корпусу), про що прямо написано в
інтерфейсі.

## 2. Шифр перестановки — 3 рівні складності

`public/js/levels.js`: `CONFIG.transposition` тепер має рівні 1 (легкий,
ключ 3-4 літери), 2 (середній, 5-6 літер), 3 (складний, 8-12 літер,
довший текст). Усе так само генерується випадково щоразу заново, працює і
українською, і англійською (залежно від поточної мови інтерфейсу).

## 3. Підключення бази даних

Раніше користувачі зберігались у масиві в пам'яті (зникали при перезапуску
сервера). Тепер `database.js` використовує **SQLite через sql.js** —
чистий WASM-порт SQLite без нативної компіляції, тож встановлюється
однаково на будь-якій машині. Файл бази — `data/bureau.sqlite`, створюється
автоматично; дані переживають перезапуск сервера (перевірено: зареєстрований
користувач лишається доступним після `Ctrl+C` → `npm start`).

Таблиця `users` зберігає обидва типи акаунтів (прізвище/ім'я і email) в
одному місці; `login_norm`/`email_norm` — нормалізовані (без регістру й
пробілів) колонки для пошуку, бо SQLite `LOWER()` не вміє в кирилицю.

## 4. Email-авторизація (додатково)

На пропускному пункті є перемикач «За прізвищем» / «За поштою». Email-гілка:

1. `POST /auth/email/register` — створює акаунт, генерує 6-значний код
   підтвердження.
2. `POST /auth/email/verify` — підтверджує пошту кодом.
3. `POST /auth/email/login` — видає JWT (тільки для підтвердженої пошти).

**Важливо:** реального SMTP-акаунта немає, тож лист фізично не надсилається.
Код підтвердження друкується в консоль сервера і повертається у відповіді
реєстрації як `devCode` — на сторінці він так само показується прямо у формі
(з приміткою, що це демо-режим). Щоб підключити справжню відправку,
достатньо замінити `console.log` у `routes/auth.js` на виклик, наприклад,
`nodemailer` з реальними обліковими даними поштового сервера.

## 5. Новий дизайн

Замість теми «архів шпигуна» (папір, друкарський шрифт) — тема «лабораторія
криптоаналітика»: темна палітра, шрифти Space Grotesk (заголовки) + JetBrains
Mono (усе інше), бірюзовий акцент, тонка координатна сітка на фоні. Усі ті
самі функції, нова шкіра.

## Postman

`postman/north-star-bureau.postman_collection.json` — 9 запитів: сайт,
Basic Auth `/login`, класична реєстрація/логін/захищений шлях, і окремо
весь email-цикл (реєстрація → підтвердження кодом → логін → захищений
шлях). Токени автоматично зберігаються у змінні колекції тестовими
скриптами на відповідних запитах.
